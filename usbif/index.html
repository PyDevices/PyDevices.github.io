usbif

usbif — native USB for MicroPython: device, host, and both at once.

usbif A board a computer sees as a sound card, a MIDI instrument, a keyboard, a drive or a webcam — and, on the same board, a USB host that a keyboard, thumb drive, MIDI controller or camera plugs into. One of the PyDevices *if modules, with displayif, audioif and cameraif: a native C module with a thin, stable Python surface that runs unchanged on a workstation.

Install

Early development: build it into firmware yourself

Nothing is released yet. usbif runs on the ESP32-S2, S3 and P4, the parts with a USB OTG controller. Patch your MicroPython 1.29 tree, point your board at the extension header, then add one line to your board's manifest.

/path/to/usbif/apply_patches.sh --apply /path/to/micropython

# in the manifest your board build already uses
include("/path/to/usbif/manifest.py")

Building has the mpconfigboard.h line and the older-than-1.29 route. The esp32 boards in micropython-pydevices already carry the header line.

Try this first

Choose what the computer sees, from Python 
import usbif.auto

dev = usbif.auto.device()
dev.functions("cdc", "uac")      # a console and a sound card
dev.functions("midi")            # a bare MIDI instrument
dev.functions()                  # -> frozenset({'midi'})

Each call re-enumerates, so the host sees a new device. examples/costume_selftest.py lists which combinations the board you run it on can wear; an S2 or S3 has fewer endpoints than a P4.
